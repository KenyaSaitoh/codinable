# jdbc-crud — Statement・PreparedStatement・ResultSet による CRUD

講座リポジトリ learn_java_db_aidd の `projects/master/03_jdbc-crud/jdbc-crud` を、Codinable で単独で動くようにしたものです。

DDL の実行には `Statement`、値を受け取る CRUD には、SQL インジェクションを防ぎ型変換を明示できる `PreparedStatement` を使います。
`ResultSet` から `Employee` へのマッピングも DAO の中に閉じ込めます。

## 読む順番

`Employee` → `EmployeeDao` → `EmployeeDaoTest` の順に読みます。

`EmployeeDao` には、主キー検索 `findById`、条件検索 `findByDepartmentId`、挿入 `insert`、一件更新 `update`、
一括更新 `raiseSalaryByDepartmentId`、一件削除 `delete`、一括削除 `deleteByDepartmentId` があります。
この例では DAO の 1 回の更新を 1 トランザクションとして確定し、検索は別の接続で DB から取り直します。
`StatementBinder` は値の設定部分を共通の実行処理に渡すための小さな関数型インターフェースです。

さらに、次の 2 つの JDBC の仕組みも扱います。

- 自動採番キーの取得 `insertAndReturnId`: 社員番号を渡さずに INSERT し、`Statement.RETURN_GENERATED_KEYS` を指定した `PreparedStatement` の `getGeneratedKeys()` から、DB が採番した社員番号（10017）を受け取る。社員番号を手で渡す `insert` も残してある（`GENERATED BY DEFAULT` なので両方動く）。
- 楽観ロック `updateSalaryWithVersion`: `UPDATE ... SET SALARY = ?, VERSION = VERSION + 1 WHERE EMPLOYEE_ID = ? AND VERSION = ?` で、読み取ったときのバージョン番号が今も同じ場合だけ更新する。先に誰かが更新していれば更新件数 0 が返る。現在のバージョン番号は `findVersionById` で読む。

テストでは CRUD、部署を条件にした検索・一括更新・一括削除の件数、該当なしの Optional／更新件数 0、重複キーの例外、引用符や SQL 構文を含む名前が値として保存されること、
自動採番された社員番号が返ること、同じバージョン番号での 2 回目の更新が 0 件になることを確認します。
DDL による削除・再作成はテストの初期化に限っています。
PreparedStatement が守るのはバインドした値であり、文字列連結したテーブル名や ORDER BY の列名まで安全になるわけではありません。

| `src/test/java/pro/kensait/db/jdbc/EmployeeDaoTest.java` | テーブルの作成と初期データの投入（DDL はここにある）、各メソッドの検証 |

## 結果のどこを見るか

- `performsCrudWithBoundParameters`・`handlesDepartmentWideSearchUpdateAndDelete`: CRUD と部署単位の検索・一括更新・一括削除の件数。
- `insertAndReturnId`: 社員番号を渡さずに登録した Walter に、DB が採番した 10017 が返り、`findById(10017)` で取り直せること。
- `updateSalaryWithVersion`: VERSION 0 を期待した更新が 1 件、同じ VERSION 0 を期待したもう 1 回の更新が 0 件になり、DB の VERSION が 1 に進んでいること。
- `reportsMissingRowsWithoutChangingOtherEmployees`・`duplicateIdFailsWithoutOverwritingCommittedEmployee`・`treatsSqlSyntaxInNameAsData`: 該当なし・重複キー・SQL 構文を含む名前の扱い。

## Codinable での動かし方

- テーブル構成と初期データは下の「この演習で使うテーブル」にまとめてあります。
- `EmployeeDaoTest.java`（`src/test/java`）を開いて、エディタの右上の **▶ 実行** で流してください。結果はテスト結果タブにメソッド単位で出ます。
- テストはプロジェクト専用のインメモリ DB（`jdbc:hsqldb:mem:crud_course`）を自分で作って使うので、DB サーバーの起動は要りません。
- このプロジェクトに main はありません（テストが入口です）。
