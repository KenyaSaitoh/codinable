# js-fetch — サーバーからデータを取って画面を更新する

チャプター 3.2「JavaScriptによるWebページ振る舞い制御」の演習です。
Fetch API で `users.json` を取得し、表の部分だけを書き換えます。
ページ全体が再読み込みされないことが要点で、これが 10 章の SPA（React）の土台です。
ここでのサーバーは Codinable の内蔵の静的サーバーで、`users.json` を返すだけです。

## 主なファイル

- `index.html` … 「読み込む」「わざと失敗させる」のボタンと、行を入れる空の表
- `app.js` … `fetch` → 状態の確認 → `response.json()` → 表の組み立て、の流れ（コメントの ①〜④）
- `users.json` … サーバーが返す社員データ（4 件）
- `style.css` … 見た目

## 動かし方

1. ▶ アプリ実行を押すと内蔵の静的サーバーが起動し、出力欄の「🌐 プレビュー」タブにページが開きます。
   最初の 1 回は自動で読み込まれ、表が埋まります
2. 次の順に試します
   - 「読み込む」を押す → 表が埋まる（URL は変わらない）
   - 「わざと失敗させる」を押す → 存在しない `no-such-file.json` を取りに行き、HTTP 404 のエラー表示になる
   - `users.json` を編集して保存し、もう一度「読み込む」→ 表の内容が変わる

## 見どころ

- `fetch` はすぐには返らない処理なので、`async` / `await` と組み合わせて書く
- 404 や 500 でも `fetch` は例外にならない。`response.ok` で状態を自分で確かめる
  （通信自体が失敗したときだけ `catch` に来る）
- 本文の読み取り（`response.json()`）も `await` で待つ
- POST で送るときの `method` / `headers` / `body` の形はコメントにあります。
  静的サーバーは受け取れないので、実際に送るのは 8 章・9 章の演習で扱います
